FIELD RULES

1) subject_id
Determine subject_id in this order:
a) if the conversation explicitly provides an ID for that exact subject label, use it
b) else if the retained block or its source-evidence context explicitly provides the subject CURIE, URI, canonical URL, profile URL, code system URL, value set URL, ontology/entity URI, model URI, schema URI, vocabulary URI, or other source identifier, use it
c) else if the retained block clearly identifies the source concept as belonging to a named source standard, code system, model, schema, profile family, ontology, terminology, vocabulary, or local controlled vocabulary, mint:
   urn:health-ri:source-concept:<source-system>:<slug>
d) else mint:
   urn:health-ri:source-concept:<slug>

Source-system detection rule:
Treat the source concept as source-qualified only when the retained block or its source-evidence context explicitly identifies the originating source system for that exact concept, for example through:
- a canonical URL
- a profile URL
- a code system URL
- a value set URL
- an ontology/entity URI
- a model URI
- a schema URI
- a vocabulary URI
- explicit wording naming the source standard, terminology, model, ontology, schema, profile family, code system, vocabulary, or local controlled vocabulary tied to the source concept

If source origin is only guessed, assumed, weakly implied, or mentioned only in unrelated narrative, do not use a source-qualified minted IRI.

Normalization for <source-system>:
- start from the explicitly identified source-system string
- lowercase
- transliterate accented characters to ASCII where possible
- replace & with and
- replace spaces, punctuation, slashes, and underscores with single hyphens
- keep only letters and digits separated by hyphens
- collapse repeated hyphens
- trim leading and trailing hyphens
- if the normalized source-system becomes empty, do not use source qualification and use the generic fallback

Slug rules:
- start from the exact subject_label
- lowercase
- transliterate accented characters to ASCII where possible
- replace & with and
- replace spaces, punctuation, slashes, and underscores with single hyphens
- keep only letters and digits separated by hyphens
- collapse repeated hyphens
- trim leading and trailing hyphens
- if the slug becomes empty, use unnamed-concept
- if two different subject labels in the same output would otherwise mint the same IRI, append -2, -3, etc.
- if the exact same subject label appears more than once, reuse the exact same minted IRI
- never mint local:<slug>
- never mint in an external or third-party namespace
