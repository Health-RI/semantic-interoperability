# Communication Plan: Health-RI Semantic Interoperability Initiative

## Overview

This plan outlines how the Health-RI Semantic Interoperability Initiative will increase visibility, gather feedback and contributions, and maintain regular updates. It covers internal and external communications (e.g., LinkedIn, calls for contributions) and how we will measure success.

## Objectives

Below are the SMART (Specific, Measurable, Achievable, Relevant, Time-bound) goals focused on communication activities and engagement.

| Objective     | Description                                                                                                                                                                                          | Target Frequency / Approach                                                                                                                                                                                                 |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Awareness     | Ensure that partners, academia, and industry know that the Initiative exists, what it tackles, the technical approach adopted, and how to engage                                                     | Newsletter: 1 issue/month (fixed day). LinkedIn (general updates): 2 posts/month. Blog: ≥ 1 article/month linked to posts.                                                                                                  |
| Feedback      | Obtain substantive feedback on ontology modules from domain experts and ontology/modeling experts; also invite discussion on design decisions, and adopted theoretical and technological background. | For each ontology module, run a Call for Contributions (2–4 weeks) and publish a feedback summary within 2 weeks of closing. Post design/theory drafts periodically for broader discussion (e.g., per module or milestone). |
| Contributions | Facilitate and encourage external contributions (mappings, corrections, use cases, etc.)                                                                                                             | Contributions are community-driven. We will make artifacts openly available (via GitHub Releases and Zenodo DOIs) and review new issues regularly to ensure responsiveness.                                                 |
| Adoption      | Stimulate usage by the community                                                                                                                                                                     | Publish each major release with release notes and update the dashboard's statistics with every release.                                                                                                                     |

## Audiences / Stakeholders

- Data stewards, modelers, and data/informatics engineers who build/manage semantic models and mappings
- Academic researchers in health informatics, ontology theory, semantic interoperability
- Clinical / domain experts (clinicians, health data users) who rely on consistent meaning across systems
- Industry / technology partners working with health and life-sciences data, software vendors, interoperability platforms
- Policymakers, infrastructure bodies, and standards organizations
- Open-source / semantic web community members interested in ontologies, persistent identifiers, mapping vocabularies

## Key Messages

- What semantic interoperability means: why it matters, what challenges it addresses, and what consistent/shared meaning across systems really entails
- Health-RI's approach: our foundations (OntoUML & gUFO), mapping vocabulary, persistent identifiers, and methodology
- What we are delivering: ontology specifications, documentation, mapping vocabularies, changelogs, published artifacts
- Progress & milestones: what has been done so far and what is coming next
- Use cases / examples of impact: how partners, modelers, and data users benefit in practice
- Design and theory rationale: decisions made, modeling rationale, underlying theory — to support understanding and invite critique
- How to contribute and give feedback: where to find drafts, how to submit feedback, and what kinds of contributions are useful
- Transparency and traceability: how we use feedback, how changes are made, version history, how to cite persistent identifiers

## Communication Channels, Formats, and Cadence

| Channel / Type                          | Periodicity / Timing                           | Use Case / Content Themes                                                                                                                                                   |
| --------------------------------------- | ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Newsletter (email)                      | Monthly (e.g., end of month)                   | Summaries, milestones, previews, calls for contribution; design/theory deep dives; case study; upcoming drafts + feedback invitation; feedback summaries                    |
| LinkedIn – General Updates              | Bi-weekly or every 2–3 weeks                   | Theory highlights, use cases, diagrams, lessons learned; why the approach matters; structure visuals; real-world examples                                                   |
| LinkedIn – Call for Contributions       | Per module (about every 1–2 months, as needed) | Draft excerpts, scope of feedback (modeling decisions, theory, design); deadlines; contribution instructions; after feedback, summary of changes                            |
| Blog / Website Entries                  | Monthly or per major milestone                 | Friendly, accessible posts for a broad audience; highlight milestones, case studies, and lessons learned; updates to visual summaries / stats page; LinkedIn teaser support |
| OntoUML/UFO Catalog                     | With each ontology version release             | Publish ontology versions for visibility among researchers                                                                                                                  |
| Workshops / Webinars / Live QA          | Occasional (aligned with milestones/events)    | Deep dives, real-time feedback, interactive discussion                                                                                                                      |
| Visual Media (infographics, dashboards) | With each release or major milestone           | Progress snapshots, statistics, version history, usage metrics                                                                                                              |
